2. Introduction

Modern supply chain operations require intelligent management of distributed transport assets, complex intermodal route optimization, and rigorous enforcement of vehicle payload limits. In an era where same-day delivery SLAs and environmental sustainability criteria dictate commercial viability, logistics operations can no longer rely on static heuristic dispatching.

LogiFlow Pro is an enterprise-grade freight logistics execution platform written entirely in pure Java. The project simulates a multi-state intermodal transport network, integrating polymorphic tariff computation, Dijkstra's algorithm for shortest-path routing with pluggable optimization criteria, greedy priority scheduling, and multi-threaded sensor telemetry tracking. Designed with zero third-party dependencies, the system runs out of the box on any terminal environment.

3. Problem Statement

Logistics management systems suffer from four systemic operational bottlenecks:

  • Heterogeneous Freight Rules: Cargo varies drastically in fragility, handling, and priority. Standardized billing fails to capture express SLA commitments or fragile insurance liabilities.
  • Multi-Dimensional Routing Constraints: Conventional pathfinding optimizes solely for distance, ignoring time-critical express deadlines, expensive commercial highway tolls, and carbon emissions.
  • Capacity Starvation: Dispatching without priority weighting allows standard bulk freight to monopolize vehicle capacities, leaving urgent medical or perishable shipments delayed at departure docks.
  • Asynchronous Telemetry Gaps: Single-threaded tracking cannot model concurrent vehicle transits or handle random road incidents like traffic delays and checkpoint inspections.

4. Functional Requirements

  • FR-1 (Fleet & Cargo Intake): Register polymorphic consignments (Standard, Express, Fragile) with polymorphic billing factoring in distance, gross weight, volume, SLA windows, and shock tolerances.
  • FR-2 (Corridor Pathfinding): Model an intermodal network of distribution hubs and transit edges. Execute Dijkstra's algorithm across pluggable optimization criteria (Fastest, Cheapest, Eco-Friendly).
  • FR-3 (Priority Dispatching): Schedule shipments using a PriorityQueue that prioritizes urgent items and matches available fleet assets based on payload weight and volumetric capacity.
  • FR-4 (Concurrent Telemetry Simulator): Asynchronously simulate vehicle journeys using a thread pool (ExecutorService) and synchronization latches (CountDownLatch), injecting random traffic delay events.
  • FR-5 (Stream Analytics): Generate operational KPIs using Java Stream API collectors (gross revenue, weight summaries, fleet utilization %, and $kg\ CO_2$ emissions).
  • FR-6 (Persistence & Audit): Persist state to CSV and log operational events to a thread-safe audit log.

5. Non-Functional Requirements

Requirement Specification
Performance & Latency Dijkstra calculations complete in <10ms; full automated test suite runs in <500ms.
Thread Safety Concurrent state updates managed via ConcurrentHashMap and synchronized blocks.
Fault Tolerance Custom checked exceptions (LogisticsException hierarchy) handle edge cases without crashing.

8. Design Decisions & Rationale

  1. Standard JDK Only: Guarantees zero friction for academic evaluators without requiring network-dependent package managers or external containers.
  2. Strategy Pattern for Multi-Criteria Routing: Decouples the Dijkstra graph traversal algorithm from the edge cost function, enabling instant runtime switching between fastest, cheapest, and eco-optimized modes.
  3. PriorityQueue Scheduling: Prevents priority inversion and cargo starvation by natively scheduling urgent medical and express freight ahead of standard bulk cargo.
  4. ExecutorService & CountDownLatch: Delivers clean thread management for concurrent vehicle tracking, preventing busy-wait CPU thrashing.

9. Implementation Details

The project comprises 20 modular classes organized into 6 packages:

  • com.logiflow.model: Abstract and concrete shipments, vehicles, network nodes, and route segments.
  • com.logiflow.service: Core business logic (routing, dispatching, telemetry, analytics).
  • com.logiflow.pattern: Factory, Strategy, and Observer pattern implementations.
  • com.logiflow.exception: Custom checked exception hierarchy.
  • com.logiflow.storage: CSV persistence and thread-safe audit logging.
  • com.logiflow.test: Standalone automated unit and integration test runner.

12. Challenges Faced

  • Path Escaping in Windows Shells: Addressed spaces in directory paths by normalizing backslashes to forward slashes in build.bat.
  • Observer Namespace Conflict: Resolved collision between deprecated java.util.Observer and our custom domain com.logiflow.pattern.Observer using explicit single-type imports.
  • Thread Synchronization: Coordinated worker threads without busy-waiting by utilizing CountDownLatch.

13. Learnings & Key Takeaways

Building LogiFlow Pro provided rigorous practical mastery of object-oriented design patterns (Factory, Strategy, Observer, Singleton), the Java Collections Framework (priority queues, concurrent maps), the Stream API for data manipulation, and multi-threaded coordination.
